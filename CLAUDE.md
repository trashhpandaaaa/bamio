# Bamio

Bamio is a clipping and editing tool: it turns long videos (YouTube, Twitch, Kick, other sites, uploads) into vertical shorts with AI-picked moments and word-by-word captions. Design phases A and B are done; the product is a Next.js app in `web/` with Clerk sign-in, Postgres (data and a durable job queue), local or S3-compatible storage (media), on-device transcription in any language (sherpa-onnx: Parakeet, Omnilingual ASR, Whisper tiny for language detection, Silero VAD), Google Gemini (clip finding), yt-dlp (link import) and ffmpeg (processing, export).

## Start of every session

1. Read `DESIGN_STATUS.md`. It says what is done, what was decided, and what to do next.
2. For design work, read `DESIGN_TOOLS.md` (installed skills and which one wins when they disagree).
3. For app work, read `web/README.md` and `web/AGENTS.md`. Next.js 16 differs from older versions: read the bundled docs in `web/node_modules/next/dist/docs/` before using an API.

## App (`web/`)

- Run: `cd web && npm run db:local && npm run dev`. `npm run setup:media` once (yt-dlp and the speech models). `db:local` starts a development Postgres in `web/.pg` on port 54329 (the unit tests start it themselves, in a separate `bamio_test` database). Without a Gemini key, set `BAMIO_AI_MOCK=1` for fake AI answers (English transcription still runs for real on the device).
- Verify before calling work done: `npm run check` (typecheck, lint, unit tests), `npm run build`, and `npm run test:e2e` (Playwright on installed Edge, mock AI). All must pass. After UI changes also run `E2E_RESPONSIVE=1 npx playwright test responsive` (every screen at 320 to 1440 wide: no sideways scroll, nothing past the edge, tap targets of 24px or more) and `E2E_SWEEP=1 npx playwright test sweep` (every screen in both themes: console errors, failed requests, axe accessibility).
- The design system lives in `web/src/styles/tokens.css` and `components.css` (copied from `design/system/`; keep them in sync). Never hard-code a color, size or radius that has a token.
- The Gemini key stays server-side: only `src/lib/ai/server/*` (marked `server-only`) may read it.
- Clip finding (`findHighlights` in `src/lib/ai/server/clips-ai.ts`) asks for `clipTarget` clips and has them rated on hype, hook and payoff; `hypeScore` makes the score. Transcripts carry per-second loudness (`src/lib/clips/loudness.ts`), measured from the transcription's audio and merged piece by piece for followed streams (`mergeLoudness`); it marks the loudest prompt lines. Test prompt changes on real transcripts with real Gemini (counts, score spread, what ranks first), not only the mock.
- Every Gemini response is validated with zod (see `src/lib/ai/server/clips-ai.ts`). Shared schemas live in `src/lib/clips/schema.ts`.
- Server-only code (`src/lib/server/*`, marked `server-only`) runs the media tools, the database and storage. Every API route goes through `userRoute` (signed-in user, cross-site check, rate limit, request id), except Stripe's webhook (`/api/billing/webhook`) and Clerk's (`/api/clerk/webhook`), which have no session and must verify the signature first, and `/api/health`, which is public and must say nothing about users or settings. Never build a file path or storage key from user input without the id checks in `store.ts`.
- Plans and payments (Stripe): the catalog is `src/lib/billing/plans.ts` (prices, minutes, projects, priority; features Bamio doesn't have yet are `soon: true` and show as coming soon: never list an unbuilt feature as included). Only `src/lib/server/billing.ts` reads `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET`. Without the key billing is off and nothing may be limited. New AI work goes through its gates: `assertCanProcess` before an import or capture, `recordUsage` once per import (keyed, so retries count once), `assertPlan` for AI on an existing video, `queuePriority` for queue order. Free plans (the owner, testers) are rows in `plan_grants`, set with `npm run plan:grant -- <email> <plan>`; `allowance` in billing.ts takes the better of a grant and a paid plan, so anything that reads the plan must go through it. The free first video (`FREE_TRIAL`) needs a card on file first, and a card starts one trial: `startTrialCard` / `confirmTrialCard` in billing.ts (a Stripe Checkout page in setup mode: the card is checked and saved, never charged, and no subscription is made) and `src/lib/server/trial-cards.ts` (Stripe's fingerprint of the card is the key; Bamio never stores a card number). Never charge the trial's card or start a plan from it, and keep the pages' promise that nothing is charged. A deleted account's fingerprint stays (tied to nobody) so the card can't start another trial; the privacy page says so. The installed Stripe SDK types the API version in use: let `tsc` check a new Stripe call's parameters, since older ones (`payment_method_types` on a Checkout session) are gone. Referrals (`src/lib/server/referrals.ts`, `settleReferral`/`creditReferrer` in billing.ts): a referrer earns `REFERRAL_REWARD_CENTS` once per friend, on the friend's first invoice with money in it, as Stripe customer-balance credit; never pay out cash, never reward a $0 checkout. After changing prices, run `npm run stripe:setup`; test gates with `E2E_BILLING=1` (see web/README.md).
- Emails (Resend): only `src/lib/server/email.ts` reads `RESEND_API_KEY`. A new email is a template in `src/lib/email/templates.ts` (zod data, subject, HTML with inline styles from `EMAIL_TOKENS`, which a test checks against `tokens.css`, plain text; Bamio's voice, no em dashes) queued with `queueEmail(userId, key, email)`, where the key names the event so it goes out once; queue it inside the transaction of the change it reports when there is one (`updateBilling`/`mutateProject` `then`). Never send from a route or a job directly: the workers' mailer sends. Videos and minutes emails can be turned off (`src/lib/profile/notifications.ts`); plan and payment emails can't. Emails are never sent to Clerk test users (`+clerk_test`). The address people write to Bamio at is `CONTACT_EMAIL` in `src/lib/contact.ts`: the campaign section, the site footer, the legal pages (`COMPANY.email`), the organization's structured data, messages that say "write to us", and where a reply to any Bamio email goes unless `EMAIL_REPLY_TO` names another. Never type the address anywhere else; it's read by a person, so the app's own alerts keep going to the superadmins unless the user asks for them there.
- The caption preview (`clip-preview.tsx`) and the export (`src/lib/clips/ass.ts`) share sizes and margins. Change them together. Other scripts use Noto fonts chosen per character from `src/lib/server/caption-fonts.json` (coverage, libass name, height; generated from the font files with fontTools) in both the export (`assMarkup`) and the preview (`/api/fonts/captions.css`). Transcript text has a space between every word; `joinWords`/`wordGap` leave it out between words of scripts written without spaces. libass here can't wrap such text, and needs `shaping=complex` for Indic scripts.
- Transcripts in every language, with a time for every word, come from `web/workers/transcribe.mjs` (sherpa-onnx in a child process; Whisper detects the language unless it was picked: tiny first, and small in a process of its own whenever tiny hears anything but English; Parakeet 0.6B v2 for English, v3 for 23 European languages, Omnilingual ASR 1B for the rest, Greek included, since v3 can't write a final sigma; `engineFor` / `engineForWindows` in `transcribe-core.mjs` decide). No model is given more than 20 seconds at once: the VAD finds no pause under music or a crowd, and longer parts come out garbled, so they're cut at their quietest moments (`splitLongSpeech`). Omnilingual transcripts are repaired where speakers switch to English (`repairMultilingual`: English checked against the English model, stretches in the wrong script decoded again with the video's own speech as context); the European model's where it wrote another language as broken English (`repairEuropean`: sentences that read as English are heard again by Omnilingual 300M); test changes on real code-mixed audio (e.g. a Nepali podcast), not only single-language clips, and measure them with `npm run lang:eval` (44 languages against YouTube's captions; `--again` re-transcribes the same videos), reading the transcripts where a number looks low, since automatic captions are a rough yardstick. A language detected wrong is the user's to fix: the language on the project page opens a picker and transcribes again (`startRetranscribe` with a language). Bump `TRANSCRIBER_VERSION` in `schema.ts` when a change is worth re-transcribing for (`retranscribeReason` offers it). Pure logic (word splitting in scripts without spaces, Indian script repair, script and English agreement checks) is in `transcribe-core.mjs`, model downloads in `speech-models.mjs` with pinned SHA-256. Don't go back to Gemini for timing: on long audio its timestamps drift by minutes (see DESIGN_STATUS.md). The native addon loads relative to the working folder: run scripts that use it from `web/`.
- Any runtime path under `process.cwd()` in server code needs `/*turbopackIgnore: true*/` on every `path.join` / `path.resolve` call, or `next build` traces that folder (it once tried to read a 1.4 GB video from `web/.data`).
- `next.config.ts` also excludes `.data`, `.models`, `.bin` and `qa` from output tracing (`outputFileTracingExcludes`), which covers webpack builds too. If Windows Smart App Control blocks `next-swc.win32-x64-msvc.node` ("An Application Control policy has blocked this file"; it happened once, briefly), Turbopack can't run: build with `npx next build --webpack` until it loads again.
- Live streams are captured by `src/lib/server/live.ts` (Twitch: its in-progress VOD via `yt-dlp --live-from-start`; others: ffmpeg records the live HLS playlist, going back as far as the playlist's history allows, stoppable with "q"; playlist helpers in `hls.ts`). "Follow the stream" (`followLive`, and `followProject` in `jobs.ts`) writes a growing HLS of MPEG-TS segments (not fMP4: ffmpeg can't seek in an fMP4 playlist past its first segment, so exports and frames came out empty) into the project's `live/` folder (synced to storage by `live-media.ts`) while the project is edited: anything that reads the video must go through `withSourceFile` (a closed snapshot of the playlist, with forward slashes: ffprobe 4 can't find the segments otherwise), and it becomes source.mp4 when it ends. Capture rules shared with the UI are in `src/lib/clips/live.ts`. A stream can change resolution part way, so the export scales every frame to the recorded size before cropping (`renderFilter`). Test with `npx playwright test live-stream` and E2E_LIVE_TWITCH / E2E_LIVE_YOUTUBE / E2E_LIVE_KICK set to channels that are live (`twitch.tv/bobross` runs around the clock but saves no VOD, so its capture-from-history test skips; live Kick channels: `kick.com/stream/featured-livestreams/en`); the follow tests export a clip from 30 s in and check the file.
- Links from other sites (`inspectUrl` in `media.ts`, helpers in `src/lib/clips/url.ts`): where a server can't read a site's page but can read its player, `playerUrl` gives the player's address and it's asked first (Vimeo; the project then keeps that address, so the download works too). A link straight to a file has no stated length: `remoteDuration` reads it with ffprobe, after the same public-address check as the link itself. `explainYtdlpError` turns yt-dlp's errors into advice (a site that turns servers away: upload the file instead); `sourceLabel` names well-known sites instead of "Web". `npm run sites:check` asks yt-dlp about one public video on each of about 15 sites: run it when a link won't import, here and on the Droplet (some sites answer one and not the other).
- Speed: a part of a video is fetched by its fragment index where the files have one (`src/lib/server/dash.ts`), else the whole file is downloaded and cut when quicker (`downloadUrl` in `media.ts`); never re-encode to cut a part. Transcription decodes several speech parts at once (`speechCpu`). `E2E_PERF=1 npx playwright test perf` times an import step by step.
- Data is in Postgres (`src/lib/server/db.ts`, postgres.js). Change the schema only with a new numbered file in `web/db/migrations/` (never edit an applied one); `npm run db:local` and `npm run db:migrate` apply it. A project is one zod-validated jsonb document: change it only through `mutateProject` in `store.ts` (row lock, transaction; queue a job in the same transaction with `then`). `DATABASE_URL` is required whenever NODE_ENV is production, so `next start` needs it too (`postgres://postgres@127.0.0.1:54329/bamio` locally).
- Media goes through `storage()` (`src/lib/server/storage.ts`: local folder or S3/R2/MinIO), at the keys from `mediaKeys`. Never write media into storage by path or serve it with fs: use `publish`, `serve`, `readable`. Work in progress belongs in `scratch(projectId)` (`BAMIO_WORK_DIR`); only finished files are published. Storage changes are tested against local and S3 (the s3rver emulator in `tests/unit/storage.test.ts`; for routes, a test server and e2e run with `STORAGE_DRIVER=s3 S3_BUCKET=bamio S3_ENDPOINT=http://localhost:4568 S3_FORCE_PATH_STYLE=1 S3_ACCESS_KEY_ID=S3RVER S3_SECRET_ACCESS_KEY=S3RVER` against `npx s3rver -d <a scratch folder> --configure-bucket bamio`).
- Background work is a job (`src/lib/server/queue.ts`, a Postgres table with leases; `worker.ts` runs them; `jobs.ts` `jobSpecs` says what each kind does). Start work only by enqueueing it, never by calling a handler from a route. Handlers must be safe to run again after a crash (another worker takes the job over when the lease runs out) and must honour their `signal` (cancel) and `stopSignal`. Throw `HttpError` under 500 for errors that retrying can't fix. A new job kind needs a migration (the `kind` check), a spec and a pool. The web server runs jobs itself (`src/instrumentation.ts`) unless `BAMIO_WORKER=off`; then `npm run build:worker` and `node dist/worker.mjs` run them. This needs long-running Node processes (not serverless). Production is one DigitalOcean Droplet with `web/compose.yaml` (Caddy, Postgres, the app; media on its disk), step by step in `web/DEPLOY.md`. The Docker image uses Debian's ffmpeg 5.1 (`FFMPEG_PATH`/`FFPROBE_PATH`), not the npm static builds (7.0 on dev machines): the static Linux builds segfault resolving host names, so ffmpeg could never read a URL on the server. Test anything that gives ffmpeg a URL on the Droplet, not only on Windows. `NEXT_PUBLIC_` settings are baked in at build time and the Docker build only gets the Clerk publishable key, so don't make the app depend on other `NEXT_PUBLIC_` values (Clerk's sign-in URLs are set in code).

- Accounts: deleting one (`src/lib/server/accounts.ts`: the profile's Delete account, or Clerk's `user.deleted` webhook) ends the Stripe subscription and removes every row and file about the user. A new table with a user id must be added to `deleteAccountData` and to `tests/unit/accounts.test.ts`. The free first video (`FREE_TRIAL` in plans.ts, `trial` in billing.ts) is for accounts that never had a plan: anything that limits by plan must go through the same gates. Legal pages (`/terms`, `/privacy`, `/takedown`) take the company's details from `src/lib/legal.ts`; while `COMPANY.ready` is false they stay unlinked and unindexed. Keep the privacy page true to the code: a new service that receives user data goes in its list.
- Clipping campaigns (`/clippers`, `src/lib/server/campaigns.ts`, `src/lib/campaigns/`): admins set up a campaign (content to clip, a rate per 1,000 views, a budget; Admin, Campaigns), clippers join, post on their own channels and send the links, and each clip counts only once an admin approves it. No money passes through Bamio: the owner pays outside it and an admin records the payment (`recordPayout`, never more than is owed); don't add anything that takes or sends money without the user asking. What clips earn is `settle` in `money.ts` (the budget shared in approval order), the only place that does the sum. Views come from `campaign-views.ts` (yt-dlp, TikTok and YouTube only; Instagram and X are typed in by an admin, and a typed number wins): before marking a site `counted`, see a real count come back, on the Droplet too. Clip and channel links must pass `clipLink` / `channelLink` (known sites only), and a share link is followed only through `resolveClipLink`: never fetch an address a user typed. Campaigns are for subscribers: `campaignAccess` in `src/lib/server/campaign-access.ts` (a working plan, paid or given; not the free trial; admins and the person who asked for that campaign excepted; everything open with plans off) is asked by `/clippers`, `/clippers/[slug]` and every `/api/campaigns/*` route, and a new page or route that shows a campaign must ask it too. Someone who may not see campaigns is told that they exist and how many are open, never a campaign's name, terms, leaderboard or clippers (not in the page's HTML or metadata either). Never put a user id or a clipper's payment details on a page. The pages read the database at request time (`await connection()`), unlike the static marketing pages. Test servers run with `BAMIO_VIEW_COUNTS=off`. Podcasters, streamers and businesses ask to run a campaign with the form on `/clippers` (`run-campaign.tsx`, `src/lib/server/campaign-requests.ts`): a request never becomes public by itself. An admin makes the campaign from it (`createCampaignFromRequest`, the New campaign form filled in from the request) or declines it, and still approves the clips and records the payments; don't let a request open a campaign, approve clips or see clippers' payment details without the user asking for owners to run their own.
- Monitoring (`src/lib/server/monitor.ts`, `context.ts`, `alerts.ts`): in production `console` writes JSON lines with the request or job; report handled errors that are Bamio's fault with `reportError` (it logs too), never user errors (`HttpError` under 500). Sentry runs only with `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN`, and the browser SDK is loaded only then. CI: `.github/workflows/ci.yml` (check, build, Docker, e2e on Chromium with the Clerk dev keys as secrets); uptime: `uptime.yml`.
- Admin panel (`/admin`, `src/lib/server/admin.ts`, `src/app/admin/`): superadmins come from `BAMIO_SUPERADMINS` (verified emails), admins from the `admins` table. Every admin page calls `requireAdmin()` and every `/api/admin/*` route uses `adminRoute`; anyone else gets a 404 (signed out too), and `/admin` stays out of `robots.txt` and the sign-in redirect. Admins view and retry or cancel jobs; only superadmins give plans and manage admins. Log every change with `logAdminAction`. A retry goes through the owner's own starter (`retryImport`, `startExport`, ...), a cancel through `cancelJob` (cancelled jobs skip the `failed` hook, so it settles the project itself). Admin e2e: `E2E_ADMIN=1` with the server's `BAMIO_SUPERADMINS` naming the e2e user.
- Search engines: a new public page goes in `USE_CASES` (`src/lib/site.ts`: its address, footer label, search title and description of 160 characters or fewer; it feeds the footer and sitemap, and the page takes its metadata from it with `metadataForUseCase`) or the sitemap directly with `pageMetadata` (title, description, canonical), and gets an `opengraph-image.tsx` (`renderOg` in `src/lib/og.tsx`); `tests/unit/seo.test.ts` checks this. One page per search: give a new page its own subject and link the neighbours (Twitch and Kick have a page each), so two pages never compete for the same words. Captions in one language (`/auto-captions/<language>`) come from `CAPTION_LANGUAGES` in `src/lib/caption-languages.ts`: add a language only after `npm run lang:eval` shows Bamio transcribes it well, say only what the transcriber really does with it (punctuation comes from `PARAKEET_LANGUAGES`, the font from `caption-fonts.json`; the test checks both), and keep its lines in the language itself short and plain, ending by saying the app is in English. Never promise a ranking, and never write a page that claims a feature Bamio lacks (posting to TikTok, translation, subtitle files). Pages behind sign-in use `robots: PRIVATE_PAGE`. Structured data only states facts (no invented ratings or reviews), with prices from `plans.ts`. After deploying changed public pages, run `docker compose exec app node scripts/indexnow.mjs` on the Droplet. The landing and use-case pages are static (built once, served as files): never read the session (`auth()`, Clerk's `<Show>` in a server component) or a server setting while rendering them, or they turn dynamic and slow; who-is-looking parts go in client components (`src/components/site/account-links.tsx`). Settings read at render are frozen at Docker build time, where only the Clerk publishable key exists. The hero headline is the page's largest paint: animate it without fading it in.
